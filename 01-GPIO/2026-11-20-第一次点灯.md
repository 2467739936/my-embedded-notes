## 学到的概念

### 1. GPIO 推挽输出（push-pull）

- 一句话：引脚内部有上下两个管子，**输出高时上管导通接到 VCC，输出低时下管导通接到 GND**，能主动给出电流
- 为什么用推挽：点 LED、驱动数字电路都要"明确的高或低"；开漏（open-drain）只能拉低，需要外部上拉
- 板子上的 PC13 是**低电平点亮**（LED 阳极接 VCC）——所以 `GPIO_ResetBits()` 才是点亮，容易记反

### 2. 时钟树：为什么 72MHz 这件事必须搞懂

```
HSE 外部晶振 8MHz → PLL ×9 → SYSCLK 72MHz → AHB 72MHz → APB2 72MHz（GPIO 挂这里）
```

- 任何外设**必须先开时钟**才能工作：`RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC, ENABLE)`
- 我原来的误解：以为"不写这句只是省电"，实际上是**寄存器写不进去、引脚完全不动**
- 验证主频是否真的 72MHz 的方法：用秒表测延时精度（如果还是内部 8MHz HSI，灯会慢 9 倍）

### 3. SysTick：内核自带的 24 位递减计数器

- 时钟源选 `HCLK/8` = 9MHz，于是**每微秒数 9 下**
- 三个寄存器：`LOAD`（重装值）、`VAL`（当前值）、`CTRL`（bit0 使能 / bit2 时钟源 / bit16 数到 0 标志）
- 1ms 就是 `LOAD = 9000`，1s 就是 `LOAD = 9,000,000`
- **精度只取决于硬件时钟**，不受编译器优化影响 —— 这是它相对空循环延时的根本优势

### 4. Flash 和 RAM 是两个地址空间

| | 地址范围 | 放什么 | 掉电 |
|---|---|---|---|
| Flash | `0x08000000` ~ `0x0800FFFF` | 代码、常量 | 保留 |
| RAM | `0x20000000` ~ `0x20004FFF` | 全局变量、栈、堆 | 丢失 |

（F103C8T6：64KB Flash / 20KB RAM）

### 5. 启动文件在做什么

`startup_stm32f10x_md.s` 里最重要的是**中断向量表**：第 0 个字放栈顶地址，第 1 个字放 `Reset_Handler`。
上电后硬件自动读这两个值 → 跳到 `Reset_Handler` → 调 `SystemInit()` 配时钟 → 调 `__main` → 初始化 RAM 里的变量 → 进 `main()`。

## 踩的坑（今晚最值钱的部分）

### 坑 1：`No Algorithm found for: 20000000H`

- **现象**：烧录报 `Error: Flash Download failed - "Cortex-M3"`，日志里 `No Algorithm found for: 20000000H - 200012C7H`
- **最初的猜测**：以为 ST-Link 驱动坏了 / 芯片锁了 / 下载算法没装
- **真正的根因**：Keil 自动生成的 `Output/blink.sct`（分散加载文件）把**代码装载地址写成了 `0x20000000`（RAM）**。烧写器要往 RAM 写程序，找不到对应算法，直接拒绝
- **怎么定位的**：`grep "Load Region" Output/blink.map` → 看到 `LR_IROM1 (Base: 0x20000000...)`，一眼发现问题
- **解法**：手写 `Project/blink.sct` 明确指定
  ```
  LR_IROM1 0x08000000 0x00010000 { ER_IROM1 0x08000000 ...   RW_IRAM1 0x20000000 0x00005000 }
  ```
  并在工程里设 `umfTarg=0`、`useFile=1`、`ScatterFile=.\blink.sct`
- **下次怎么快速判断**：烧录报 "No Algorithm"，先 `grep "Load Region" xxx.map` 看地址对不对，比到处翻驱动快得多

### 坑 2：`UV4.exe -f` 失败也返回 exit 0

- **现象**：批处理烧录返回 0，以为成功了，其实报错
- **根因**：uVision 的批处理模式**退出码不可信**，必须读 `-o` 指定的日志
- **正确做法**：成功日志包含 `Erase Done. Programming Done. Verify OK. Application running`
- **教训（重要）**：**"命令成功退出" ≠ "事情做成了"**，永远校验真实结果

### 坑 3：烧完 PC13 不亮，按一下 RST 才运行

- **现象**：日志显示 `Application running`，但灯不亮；按板子上的 `RST` 后正常
- **根因**：命令行烧写后芯片仍停在调试器的暂停态
- **解法**：按 RST，或重插 USB；GUI 里在 `Flash Download` 勾 `Reset and Run`

### 坑 4：MDK 5.39 不再自带 ARM Compiler 5

- **现象**：江协老工程默认用 AC5（`C:\Keil_v5\ARM\ARMCC`），5.39 里根本没有这个目录
- **解法**：`Options for Target → Target → ARM Compiler` 改成 **V6（ArmClang）**，老代码无需改动就能编
- **附带认知**：不用去网上找破解版 AC5，V6 是 Arm 官方推荐的编译器
